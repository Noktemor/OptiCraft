# OptiCraft — прототип бинарного архива деревьев TREE v1

## Сделано

- В `assets/trees/trees.tree` хранится **один бинарник с индексом 576 деревьев**: 16 видов (`Tree_Type`), по **36 шаблонов** каждого. Имена в индексе: `Oak1`, `Birch1`, `Acacia2`, ...; нет отдельного файла на дерево.
- Офлайн-сборщик `tools/treepack/treepack.cpp` записывает готовые воксельные шаблоны; старые процедуры `Tree_Generator` переиспользуются для большинства форм. Для обычных берёз и елей добавлена офлайновая вариативность высоты/ветвей/«зазубрин». На остальные виды добавляются небольшие случайные выступы листвы. *В игре генератор форм не запускается.*
- Архив загружается **один раз**, после инициализации реестра блоков и до запуска генерации мира. В горячем пути доступны только read-only массивы. Из файла не читают при размещении каждого дерева, новых мьютексов/очередей/worker'ов нет.
- Выбор одного из 36 шаблонов: детерминированный цикл по пространственной сетке 6×6 ячеек по 16 блоков; для каждого региона и вида вычисляется смещение от seed. Таким образом, соседние области имеют разные циклы, а порядок выполнения многопоточных задач не влияет на выбор формы. Это **пространственный**, а не общий изменяемый счётчик деревьев.
- В обычной генерации мира вызовы идут через существующий `World_Generator::decorate_column` и **существующие block setters**. `Chunk_Manager` и `Renderer` не изменены.
- В росте обычных саженцев используется тот же `Tree_Generator::place_tree`, затем **существующий** `Sapling_Manager::try_grow -> Chunk_Manager::set_blocks_world_batch`. Никакой дополнительной обработки чанков или пересборки мешей на каждый блок не добавлено.
- Особые ели из групп 2×2 / 3×3 оставлены на прежнем `place_spruce_medium/large`; пещерный Glowwood с высотой, зависящей от потолка, оставлен процедурным. Это предотвращает изменение их специфических правил.
- Нет изменений формата сохранения мира и чанков. Повреждённый/отсутствующий архив не останавливает игру: используются прежние процедуры.

## Как включить

Начиная с прототипа деревень, **TREE pack включён по умолчанию**: достаточно
запустить обычную конфигурацию OptiCraft в CLion. Файл `assets/trees/trees.tree`
должен быть доступен в рабочей директории (CMake копирует `assets` к исполняемому файлу).
При отсутствии или повреждении файла используется прежний генератор деревьев.

Для временного отключения и A/B-сравнения доступна необязательная переменная
`OPTICRAFT_TREE_PACK=off` (или `0`). Она **не нужна** для обычного тестирования.

**Важно:** Новые и старые чанки могут отличаться деревьями на границах
сохранённых территорий. Тестировать генерацию на новом мире или копии сохранения.

## Формат TREE v1

Все целые — little-endian. Смещения абсолютные от начала файла. В индексе имя ASCII, дополненное нулями. Каждая вариация содержит уникальные относительные координаты; пересечения при конструировании шаблонов разрешаются при офлайновой сборке (последняя запись побеждает).

| Часть | Размер | Поля |
|---|---:|---|
| Header | 16 байт | `magic="TREE"` (4), `version` (u16), `count` (u16), `index_offset` (u32), `payload_offset` (u32) |
| Index entry | 32 байта | `name[16]`, `species` (u16), `variant` (u16, 0..35), `offset` (u32), `block_count` (u32), `reserved` (u32) |
| Block entry | 8 байт | `dx` (i16), `dy` (i16), `dz` (i16), `block_id` (u16) |

Парсер проверяет magic/version, длину, границы индекса/данных, дубликаты пар `species/variant`, корректность имён, допустимый диапазон количества блоков, максимальный размер файла. Если проверка не прошла — не применяется частично разобранный архив.

Размер предоставленного `trees.tree`: около **1,1 МБ** (без сжатия).

## Как пересобрать архив

После правок в `tools/treepack/treepack.cpp` или в исходных процедурах дерева:

```bash
cmake -S . -B cmake-build-release -DCMAKE_BUILD_TYPE=Release
cmake --build cmake-build-release --target treepack -j 4
./cmake-build-release/treepack assets/trees/trees.tree
```

После этого стандартная сборка OptiCraft копирует обновлённый архив вместе с `assets`.

## Протестировано

- `python3 tools/tests/test_tree_pack.py`: проверка индекса, 576 записей, границ, содержимого, 36 **различных** шаблонов у каждого вида — прошла.
- C++ smoke (`tools/tests/tree_pack_smoke.cpp`): выбор при одинаковых координатах и seed стабилен, сетка 6×6 использует все вариации, параллельные обращения из 8 потоков дают одинаковый результат — прошло.
- Режим `off` и отсутствие файла — fallback к старому процедурному дереву — прошло. Режим без переменной окружения теперь включает архив автоматически.
- `python3 tools/tests/test_worldgen_fastpaths.py`: `worldgen fast-path checks passed: 78197 scenarios` — прошло.
- Проверены компиляция и выполнение **автономного** `Tree_Generator + Tree_Pack + treepack` с C++20. В тестовом окружении нет GLFW/GLM для полной сборки игры, поэтому standalone smoke проверен с минимальной заглушкой объявления `glm::vec4` **только в тестовой сборке**. Эта заглушка **не включена** в проект.

## Осталось

- Полная сборка и запуск игры на машине с OpenGL/GLFW/GLM.
- A/B-профилирование в Release/Tracy: скорость генерации чанков, 1% low, рост деревьев из саженцев и пиковая стоимость перестройки геометрии.
- Проверить крону каждого вида визуально и скорректировать формы в офлайновом сборщике.
- Добавить версионирование шаблонов на уровне конкретного мира, если архивный режим станет постоянным.

## Архитектурные границы

**Не тронуты:** `Chunk_Manager.*`, `Renderer.*`, `Chunk_IO`, очереди задач, механизм освещения, GPU-мешинг, формат регионов и сохранений. `Tree_Pack` — только immutable-источник данных для `Tree_Generator`; это не новый конвейер.
