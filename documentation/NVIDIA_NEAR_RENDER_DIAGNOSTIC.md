# NVIDIA: первый меш ближних чанков — диагностический патч

## Симптом

На RTX 4060 Laptop GPU в любом профиле рендера рядом с игроком возникают крупные
провалы поверхности и тёмная геометрия. Изменение блока приводит к пересборке
чанка, после которой его отображение нормализуется. Предыдущая правка соседних
границ не устранила проблему.

## Гипотеза

У LOD1 (ближние чанки) есть путь `gpu_light_volume`: вместо запечённого света
и AO фрагментный шейдер читает отдельный `34×34×34` volume SSBO по GPU-ручке.
Дальние LOD используют baked light. Обычный «Совместимый» профиль NVIDIA
отключает mesh shaders/Hi-Z, **но не этот общий фрагментный путь**.
Несогласованность светового объёма, его GPU-ручки или ограничений SSBO может
объяснить часть артефактов. Это пока **гипотеза**, не подтверждённая трассировкой RTX.

## Сделано

- NVIDIA определяется при инициализации `Renderer` через `GL_VENDOR`. Для неё
  по умолчанию используется **существующий baked-light/AO путь** и для LOD1,
  как раньше для дальних чанков. На остальных GPU прежний volume-light путь
  остаётся включённым.
- Согласовано решение между `Chunk::mark_light_dirty()`, `Chunk_Manager` и
  `Renderer::submit_gpu_batch()`: на NVIDIA световая правка запускает обычную
  пересборку геометрии, поэтому baked-квады не получают устаревший свет.
- Когда volume-light отключён, `Renderer` не выделяет отдельный SSBO световых
  объёмов и не запускает лишний compute-pass для них. Существующий compute
  greedy/misc mesher, quad pool, GPU COW и indirect draw сохранены.
- `terrain_gpu_fragment.glsl`: индекс в световом halo при округлении пикселя
  на границе чанка ограничен областью `[-1,32]` по каждой оси. Это предотвращает
  чтения за пределами светового объёма на устройствах, где он используется.
- При увеличении geometry pool и light-volume таблиц выводится предупреждение,
  если требуемый размер выходит за `GL_MAX_SHADER_STORAGE_BLOCK_SIZE`.

## Осталось

- **Не подтверждено**, исчезают ли артефакты в реальном кадре RTX 4060.
  Для этого необходим игровой прогон на машине с NVIDIA.
- Проверить одинаковый участок мира **до** и **после** установки/разрушения блока,
  затем без изменения блока через 5–10 секунд после окончания загрузки.
- Следить за FPS и `GPUSTAT`: baked-light может повысить стоимость мешинга,
  поскольку уменьшает эффективность greedy merging.
- Если артефакты сохранились, следующее действие — захват RenderDoc и сравнение
  `ranges`, `counts`, `quads` и `baseInstance` для повреждённой и перестроенной секции.
  Дальше менять GPU-пул или добавлять backend без такого замера не рекомендуется.

**Режим NVIDIA активируется автоматически**, без переменных окружения и
действий пользователя. Новых worker-очередей и конвейеров нет.
