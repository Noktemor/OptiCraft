# OptiCraft — прототип деревень и бинарных структур OSTR v1

## Сделано

- Встроены **живые деревни вместо алмазных столбов**. Сохранён исходный `Structure_Placement` с Worley/Voronoi-ячейками 320×320, проверкой ровности, близости реки и выбором радиуса 60–120. Семена и координаты определяют результат; глобального RNG или счётчика задач нет.
- `Village_Layout` строит immutable-план: центр с колодцем, четыре слегка изгибающиеся дороги шириной три блока, участки по обе стороны, проверку перепада высот в четырёх углах, выбор коттеджа/фермы и ориентацию входа к дороге. Количество домов определяется доступной длиной дорог, высотой местности и seed.
- `Structure_Pack` загружает **один** `assets/structures/structures.struct` при инициализации генератора мира. Все пять шаблонов доступны из RAM, файл во время декорирования не читается: `Cottage_Oak`, `Cottage_Birch`, `Farm`, `Well`, `Fortress`.
- В `.struct` находятся версии формата, индекс имён, абсолютные смещения, габариты, точка входа, ID блоков, относительные координаты, метаданные и флаг поворота метаданных. Двери двухблочные, верхняя половина имеет bit 3, обе половины поворачиваются к дороге.
- Поддержан `Structure_Instance`: готовый шаблон можно повернуть на 90°, 180°, 270°; `custom_template` позволяет передавать готовый процедурный лабиринт/данж через тот же механизм. `Structure_Adapters.h` адаптирует существующие `Maze_Generator::place` и `Dungeon_Layout` без изменения исходных генераторов.
- `Structure_Placement` кеширует планы на уровне ячейки (до 256), результат воспроизводится при сбросе кеша. При параллельной генерации все worker'ы читают один неизменяемый план. Кеш не является источником истины.
- `World_Generator::place_villages_in_chunk` применяет **только пересечение с текущим чанком**: сначала дороги, затем полные шаблоны зданий и очистку их внутренних помещений. Никаких прямых изменений соседних чанков.
- Размещение подключено в **существующем** `Chunk::finish_generation` после травы/деревьев, до уплотнения палитры и пересчёта метаданных. CPU/GPU worldgen, очередь jobs, `Chunk_Manager`, `Renderer`, освещение и форматы сохранений не изменялись.
- Обычные деревья не растут на территории существующих деревень. Ограничение `chunk_is_definitely_air` учитывает максимальную высоту построек без прежнего `INT_MAX` для алмазного маркера.
- Пак `trees.tree` также включён **по умолчанию**, чтобы новое поведение сразу проверялось запуском из CLion. Временный откат: `OPTICRAFT_TREE_PACK=off`.

## Как тестировать

1. Открой проект в CLion и запусти обычную конфигурацию **без переменных окружения**. Новые деревья и деревни включены по умолчанию.
2. Создай **новый тестовый мир** и найди поселение. Позиции продолжает определять существующий шум `Structure_Placement`. Колонн из алмазов больше не будет.
3. Проверь стыки дорог, домов, дверей, высоты и подгрузку при перемещении через чанки. Рекомендуется `Release` и сравнение во время быстрого полёта по миру.
4. При желании пересобери шаблоны: `python3 tools/structurepack/build_structures.py`. Стандартная сборка копирует готовый `.struct` вместе с остальными `assets`.

Тесты без запуска игры:

```bash
python3 tools/tests/test_village_structures.py
python3 tools/tests/test_worldgen_fastpaths.py
python3 tools/tests/test_tree_pack.py
```

`test_village_structures.py` проверяет двоичный индекс, C++-парсер, повороты, 2 половины дверей, сшивание частей здания и большой 65×65 крепости, воспроизводимость плана, восемь потоков и адаптеры исходного лабиринта/данжа. Небольшая тестовая заглушка GLM создаётся **только во временной директории теста**. В продукт она не входит.

## Формат `OSTR v1`

Все числа — little-endian; неизвестные версии и некорректные записи отклоняются. Файл содержит пять записей в порядке enum `Structure_Template_Id`.

| Область | Размер | Поля |
|---|---:|---|
| Заголовок | 16 байт | `magic="OSTR"`, `version` (u16=1), `count` (u16), `index_offset` (u32), `payload_offset` (u32) |
| Запись индекса | 44 байта | `name[24]`, `width/height/depth` (u16), `entrance_x/z` (i16), `offset` (u32), `blocks` (u32), `flags` (u16) |
| Запись блока | 10 байт | `x/y/z` (i16), `block_id` (u16), `meta` (u8), `flags` (u8; bit0 — вращение direction meta) |

Один архив — около 1,05 МБ (большую часть занимает пример крепости). Пак создаётся офлайновым Python-скриптом из заданных объёмов и реестра `assets/blocks.json`.

## Добавление большой структуры / существующего лабиринта

`Fortress` уже лежит в бинарном паке и проверена на разрезание по границам чанков, **но пока не включена в случайное появление**, чтобы не менять плотность мира и не тратить ресурсы при первом тесте деревень. Её можно добавить как один `Structure_Instance`, а не генератор, записывающий мир вручную.

Для лабиринта:

```cpp
// Однажды при создании плана области, не внутри каждого чанка:
Maze maze = Maze_Generator::generate(config, rng);
Structure_Instance instance;
instance.entrance_world_x = world_x;
instance.base_world_y = world_y;
instance.entrance_world_z = world_z;
instance.rotation = 0;
instance.custom_template = std::make_shared<Structure_Template>(
    make_maze_structure_template(maze));
plan.buildings.push_back(std::move(instance));
```

Важно: план должен включать полную область структуры в `min/max` и запрашиваться для всех пересекающихся чанков. Текущий запрос планов ограничен **радиусом деревни + 12 блоков**, так как пока встроены именно деревни. Для гигантских независимых данжей потребуется отдельный детерминированный индекс крупных объектов по регионам — без новых очередей или изменений `Chunk_Manager`.

## Протестировано

- C++ smoke `village_structure_smoke` — корректность данных, детерминизм, повороты дверей, 65×65 крепость и сборка из соседних чанков, 8 потоков, адаптер лабиринта — прошло.
- C++ smoke `structure_placement_smoke` — выбор 72 центров на тестовой плоской области, 17 170 точек дорог, отрицательные координаты, кеширование планов, 8 потоков — прошло.
- `test_worldgen_fastpaths.py` — 78 197 сценариев — прошло с новой проверкой верхней границы по высоте.
- `test_tree_pack.py` — 576 проверенных вариаций деревьев — прошло.
- Синтаксическая компиляция изменённого `World_Generator.cpp` с временными заголовками GLM — прошла.

## Осталось

- Полная сборка/запуск в CLion на системе с реальными GLFW/GLM/OpenGL, профилирование Release/Tracy (работа в игровом окружении **ещё не проверена**).
- Проверить реальные дороги на обрывах, берегах, руслах и у соседних деревень. Текущие дороги лишь повторяют высоту и не прокладывают мосты/лестницы.
- Продумать полноценный индекс произвольно больших *независимых* структур. В эту итерацию уже включено универсальное представление шаблона и `Structure_Instance`, но не универсальный глобальный планировщик всех структур.
- Повороты некоторых будущих типов блоков могут потребовать специальных правил (двери и базовые направленные ступеньки учтены флагом).
- `Dungeon_Layout` содержит сундук, но блок-сущность/лут не создаётся одним только размещением его блокового ID. Это отдельная задача интеграции с `Block_Entity_Store`.
- Тестировать на **новом мире или резервной копии**: сохранённые чанки с прежними алмазными маркерами не перегенерируются автоматически, а границы уже созданной территории могут различаться.
