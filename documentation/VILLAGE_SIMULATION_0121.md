# OptiCraft 0.12.1 — жители, профессии, торговля и деревни

## Сделано

### Профессии и рабочие места

| Профессия | Рабочий блок | ID |
|---|---|---:|
| Фермер | Composter | 533 |
| Лучник / стрелодел | Fletching Table | 530 |
| Библиотекарь | Lectern | 427 (существующий) |
| Охотник | Hunter Bench | 531 |
| Повар | Smoker | 532 |
| Кузнец | Smithing Table | 534 |

Житель занимает ближайшее свободное рабочее место; один рабочий блок принадлежит не более чем одному жителю. При разрушении блока профессия может измениться при следующем сканировании. Без профессии торговля недоступна. Для каждого типа добавлено три обмена и собственная модель. Валюта — Emerald, ID 535.

### Меню торговли

- ПКМ по взрослому жителю с профессией открывает меню в стиле существующей панели инвентаря.
- Три предложения с иконками стоимости и результата; ЛКМ по результату покупает предмет.
- Инвентарь игрока показывается внизу; клик/перетаскивание работает через стандартную модель Inventory.
- Обмен атомарный: при нехватке товаров или свободных слотов ни валюта, ни покупка не теряются.
- `E` или `Esc` закрывает торговлю; открытый торговец отслеживается по постоянному идентификатору.

### Дома, распорядок и размножение

- Сканируются **загруженные** блоки около игрока; дом — закрытое помещение с кроватью, дверью, крышей, достаточной площадью и факелом.
- Каждая кровать даёт одно свободное место; каждый житель занимает не более одного места.
- Новые генерируемые коттеджи содержат дверь, кровать, факел и рабочее место. Ферма содержит компостер и зрелую пшеницу.
- По ночам жители пытаются вернуться к своему дому, открывают дверь, заходят и закрывают её. Для маршрута применяется общий асинхронный A*.
- Рождение ребёнка возможно при наличии двух взрослых жителей, свободной кровати, взрослого фермера и зрелого урожая рядом. Ребёнок взрослеет со временем. Применяются интервалы и ограничения численности.
- Начальное заселение: при обнаружении новых домов около игрока появляется до двух жителей; дополнительные жители появляются при выполнении условий размножения.
- При появлении врагов поблизости жители паникуют и убегают.

### Железные големы

- Пороги жителей одной деревни: **5 / 12 / 22 / 35 / 51 / 70 / 92**, максимум **7** големов на деревню.
- Деревня определяется как связанная группа домов с расстоянием до следующего дома не более 48 блоков.
- Големы патрулируют деревню и атакуют ближайших существующих враждебных мобов; при ударе по жителю или голему игрок получает агрессию големов.
- Големы используют ту же очередь A*; атака игрока применяется через стандартную систему урона и брони, только в Survival.
- Перед появлением проверяется свободное место для корпуса и опора под ногами.

### Сохранение

- Жители, возраст, здоровье, профессии, привязка к кровати/рабочему месту, големы и их здоровье сериализуются отдельно в `villagers[_dimension].txt`.
- Жители создаются только в Overworld. Переход между измерениями сохраняет их, затем подгружает при возвращении.
- Существующие деревни **без кровати/факела** не превратятся автоматически в жилые. Новый мир или построенные игроком дома нужны для проверки.

- Python `tools/tests/test_village_0121_contracts.py`: JSON-реестр и рецепты, атлас, GLB-модели, структуры, подключение в Game, версия.
- `tools/tests/test_village_structures.py`: существующие тесты генерации и размещения структур.

## Осталось

- Полная сборка и интерактивная проверка в CLion/OpenGL: в тестовом окружении нет development-зависимостей GLFW/GLM.
- Новые GLB — оригинальные **статические** voxel-модели. Для взмахов рук и ног требуется добавить скелет и анимационные клипы.
- Торговля пока содержит три фиксированных обмена на профессию: нет уровней торговли, скидок, пополнения запасов, интерфейса опыта жителя и репутации.
- Навигация остаётся ограниченной локальными участками A*. Сложные многокомнатные дома, узкие проходы и двери разных ориентаций нужно отдельно проверить в реальной игре.
- Пока нет переработки угрожающих мобов с прицеливанием непосредственно по жителям: голем атакует уже существующих враждебных мобов у деревни.
- Сканирование домов около игрока выполняется периодически; для очень больших поселений в будущем желателен чанковый индекс кроватей и рабочих мест.
